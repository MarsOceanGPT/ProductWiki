# AI 产品策略图谱 — 知识库架构设计 v2.0

> 设计者：Mars × Claude | 2026-03-14
> 目标：建立一个可规模化、可持续更新、AI 可读 + 人可读的 AI 产品策略知识网络

---

## 一、设计原则

1. **课程骨架即分析框架**：用 Mars 的课程模块（机会发现 → 产品设计 → MVP 验证 → PMF 切入 → 增长引擎 → 商业变现 → 壁垒构建）作为每个产品的"成长旅程"分析主线。课程和知识库天然互哺——案例喂课程，课程定义分析维度。
2. **双向链接是核心**：每个产品卡片链向它用过的打法，每个打法页面反向汇聚所有使用该打法的产品。网络结构是知识库的灵魂。
3. **三层粒度**：阶段（Stage）→ 策略类别（Strategy）→ 具体打法（Tactic）。粗看有结构，细看有干货。
4. **AI 可解析**：关键字段用 YAML frontmatter 标准化（Obsidian 笔记顶部用 `---` 包裹的结构化数据，Dataview 插件可查询，未来也方便接 RAG / MCP / API），方便机器读取。
5. **人可阅读**：正文部分用自然语言写，不是填表，是讲故事。

---

## 二、知识库的三类页面

### 类型 A：产品卡片（Product Card）

> 一家公司/产品一张卡。这是知识库的"原子单位"。

### 类型 B：打法页面（Playbook Page）

> 一个策略/打法一张页面。汇聚所有使用该策略的产品案例。

### 类型 C：人物页面（People Page）

> 一个关键人物一张页面。思想演进、关键判断、代表观点。

三类页面通过双向链接形成网络：

```
[产品] --使用了--> [打法]
[打法] --被使用于--> [产品]
[人物] --创建/运营--> [产品]
[人物] --提出/实践--> [打法]
[产品] --竞争于--> [产品]
[打法] --属于阶段--> [阶段]
[打法] --相关打法--> [打法]
```

```markdown
## 三、战略框架

用 Mars 的原创分析框架对这个产品做"战略体检"。

### 3.1 时代红利（Why Now）

为什么是现在？什么变了？
如果这个产品早两年做会怎样？晚两年呢？
它吃到的是哪一波红利——模型能力突破、成本下降、生态成熟、认知普及、监管变化？

### 3.2 核心优势

用配置论分析——它选择在什么维度竞争？
这个优势是比较优势（在已有维度做得更好）还是引入新变量（重新定义竞争维度）？
Cursor for X 评估：工作流复杂度、重复劳动量、反馈机制清晰度。
距钱距离：这个产品离实际的钱交换有多远？

### 3.3 生态位

产业分层位置：基础设施层 / 模型层 / 中间件（"工头"层）/ 应用层。
它控制的是哪一层？有没有往控制层靠拢的趋势？
AI 定价象限：自主性 × 可归因性，决定了定价天花板在哪。
反脆弱评估：下行风险是什么？上行空间在哪？杠铃策略是什么？
```

## 五、打法分类体系（三层结构）

第一层 = 阶段，第二层 = 策略类别，第三层 = 具体打法。

### 阶段 1：机会发现（Opportunity Discovery）

对应课程模块 2-3

**1.1 需求侧机会识别**
- JTBD 用户任务拆解
- 客户旅程痛点扫描
- 困难步骤 AI 赋能

**1.2 供给侧机会识别**
- 吃技术升级红利（模型能力突破 → 新场景）
- 把玩法封装成产品（AI native 工作流产品化）
- 滥用算力（在服务中加入 1000 倍智能）

**1.3 市场结构机会**
- 打开价格门槛新市场（AI 降低成本 → 下沉市场）
- 打开能力门槛新市场（AI 降低技能要求 → 新用户群）
- Agent 原生新市场（以 Agent 为目标用户）

**1.4 价值重新定义**
- 从做任务到出成果（重新定义交付物）
- 从工具到工人（交付 AI 劳动力而非软件）

### 阶段 2：产品设计（Product Design）

对应课程模块 4

**2.1 交互范式选择**
- Chat 对话式
- Copilot 助手式
- Canvas 画布式
- Agent 代理式
- 生成式界面
- 沉浸式（环境感知）
- CLI 命令行式

**2.2 智能设计模式**
- Prompt Engineering
- Context Engineering
- Harness Engineering

### 阶段 3：MVP 验证（Validation）

对应课程模块 5

**3.1 验证策略**
- 人力替代（先用人跑通，再用 AI 替换）
- 服务先行（不封装产品，直接提供服务）
- 简易拼装（借现有基础设施轻装上阵）

### 阶段 4：市场切入 / PMF

对应课程模块 6

**4.1 切口选择**
- 迫切刚需（用户现在就痛）
- 别无选择（没有替代方案的场景）
- 技术适配（现在的 AI 恰好能做到）

**4.2 聚焦策略**
- 关键功能聚焦（功能越窄，PMF 越强）
- 关键业务聚焦（找到能建根据地的细分）
- 关键资源聚焦（独特数据或渠道壁垒）

### 阶段 5：增长引擎（Growth）

对应课程模块 7

**5.1 常规增长**
- 付费投放
- 红人/KOL 合作
- SEO / 内容营销

**5.2 病毒传播**
- 产品即内容（使用过程自然产生可传播内容）
- 社交裂变（分享机制内置于产品）
- 话题引爆（制造争议或好奇心事件）

**5.3 生态增长**
- 开源合作（用开源建立生态和认知）
- 借势崛起（吃平台/模型升级红利）
- 并购发展（收购产品或客户基础）

**5.4 主动获客**
- AI 主动扫描需求（AI 找客户而非等客户来）
- Outbound AI（自动化外呼/触达）

### 阶段 6：商业变现（Monetization）

对应课程模块 8

**6.1 按访问收费**
- 订阅制
- 席位制
- 会员制

**6.2 按消耗收费**
- Token / 请求数
- 信用点
- 会话数 / 时长

**6.3 按成果收费**
- 完成计费
- 成交分成
- ROI 挂钩

**6.4 其他模式**
- 定制化服务
- 广告变现
- 资本变现（AI Rollup）
- 混合模式

### 阶段 7：壁垒构建（Moat）

对应课程模块 7 后半段

**7.1 AI 即壁垒**
- 技术领先 = 体验领先 = 引流效果
- 模型微调 / 专有模型

**7.2 AI 之外的壁垒**
- 数据飞轮（越用越好的正循环）
- 工作流嵌入（切换成本高）
- 品牌信任（专业领域的信任积累）
- 网络效应（用户间相互依赖）
- 监管壁垒（合规资质）

## 六、子打法的处理规则

"病毒传播"下面有很多细分打法，其他大类也一样。处理方式：

**主打法页面**：[[病毒传播]] — 概述性页面，链向所有子打法

**子打法页面**（独立成页，各自有案例）：
- [[02-打法库/05-增长引擎/病毒传播-产品即内容|病毒传播-产品即内容]]：使用过程自然产生可分享内容（Wordware、Manus）
- [[病毒传播-社交裂变]]：产品内置分享/邀请机制（Midjourney）
- [[病毒传播-话题引爆]]：制造争议或好奇心事件（Cluely）
- ...

**规则：当一个子打法下有 3+ 个案例时，独立成页。少于 3 个时，暂时放在主打法页面下。** 随着案例增加自然分裂。

Obsidian 标签层级管理：`#growth/viral/product-as-content`

```
├── AI 动作：按 7 阶段 + 3 个战略框架写正文草稿
├── AI 动作：识别并标注打法标签
├── AI 动作：填写"其他"中有趣但不好归类的发现
└── 输出：产品卡片草稿（.md 文件）

Step 2：Mars 审核
├── 检查事实准确性
├── 补充 AI 找不到的信息（内部消息、个人判断）
├── 撰写"Mars 点评"段落
├── 调整打法标签
├── 补充"其他"中你觉得精彩的细节
├── 设置 confidence 等级
└── 标记 mars_reviewed: true

Step 3：自动关联
├── 打法标签自动出现在对应打法页面的案例列表
├── 涉及新人物 → 创建人物页面草稿
├── 涉及新打法 → 标记待 Mars 确认是否新增
└── 更新竞品关系
```

### 新增一个打法

```
Step 1：触发条件
├── Mars 在课程/文章/播客中提到一个新打法
├── 或：多个产品出现相同模式，AI 识别出潜在新打法
└── 或：Mars 主动定义

Step 2：AI 生成草稿
├── 定义打法名称（中英文）
├── 归入三层分类树的合适位置
├── 搜索并列举使用该打法的产品
├── 写正文（定义、案例、使用方法、风险）
└── 建立与相关打法的链接

Step 3：Mars 审核
├── 确认是独立打法 vs 已有打法的变体
├── 调整分类位置
├── 补充实操建议
└── 撰写 Mars 点评
```

## 九、AI 录入的 Prompt 模板

给 AI 做 Deep Research 时使用的标准提示词：

```
你是一个 AI 产品分析师，正在为「AI 产品策略图谱」知识库录入一个新的产品条目。

请对 [产品名] 进行深度研究，按以下结构输出完整的产品卡片：

## 一、基本面
公司全名、创始年份、总部、创始团队、融资历程、当前阶段、关键指标（ARR/用户数/估值）。
用 2-3 段自然语言概述这个产品是什么、做什么、给谁用。

## 二、成长旅程（7 阶段）

### 2.1 机会发现
创始人看到了什么市场信号？属于哪种机会类型（需求侧/供给侧/市场结构/价值重定义）？关键洞察是什么？
标注相关打法标签。

### 2.2 产品设计
核心交互范式（Chat/Copilot/Canvas/Agent/其他）。关键设计决策及其理由。
标注相关打法标签。

### 2.3 MVP 验证
最早的产品版本。首批用户来源。属于哪种 MVP 策略（人力替代/服务先行/简易拼装）？
标注相关打法标签。

### 2.4 市场切入 / PMF
选择了什么细分市场？PMF 的信号是什么？属于哪种策略（迫切刚需/别无选择/技术适配 × 功能/业务/资源聚焦）？
标注相关打法标签。

### 2.5 增长
关键增长事件和时间线。使用了哪些增长引擎（投放/红人/SEO/病毒传播/开源/借势/并购/主动获客）？
标注相关打法标签。

### 2.6 商业变现
定价策略及演变。收入结构。属于哪种变现模式？
标注相关打法标签。

### 2.7 壁垒
护城河类型。被颠覆的风险。
标注相关打法标签。

## 三、战略框架

### 3.1 时代红利（Why Now）
为什么是现在？它吃到的是哪一波红利（模型能力突破/成本下降/生态成熟/认知普及/监管变化）？

### 3.2 核心优势
用配置论分析——选择在什么维度竞争？比较优势还是引入新变量？
Cursor for X 评估（工作流复杂度/重复劳动量/反馈机制）。
距钱距离评估。

### 3.3 生态位
产业分层位置（基础设施/模型/中间件/应用）。
AI 定价象限（自主性 × 可归因性）。
反脆弱评估（下行风险/上行空间/杠铃策略）。

## 四、其他
任何精彩有趣但不好归入上述框架的发现——反直觉的决策、有意思的内部故事、独特的组织设计、出人意料的 pivot、跨领域类比等。

## 关键时间线
按时间排列的里程碑事件表。

## 竞品
主要竞争对手及竞争维度。

要求：
- 所有事实需有来源支撑
- 区分"已确认事实"和"推测/分析"
- 信息不足的阶段明确标注"信息不足，待补充"
- 输出完整的 YAML frontmatter + 正文
- 打法标签使用知识库已有的标签体系（见打法分类树）
```
