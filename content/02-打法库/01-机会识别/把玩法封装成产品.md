# 把玩法封装成产品

> 将高手社区已经验证的使用技巧、工作流封装成产品的标准功能，让普通用户开箱即用高手级的效果。

## 这个打法的本质

这是一个常被忽视但威力巨大的打法。每个产品都有 power user，他们通过大量的摸索和实践，开发出了最高效的使用方式。比如 Notion power user 用快捷键和模板库，效率比普通人高 10 倍。这个差距，根本不是产品不好用，而是"高手知道怎么用，普通人不知道"。

如果你能观察、总结、系统化这些高手的玩法，然后把它们直接产品化成内置功能或默认工作流，就能快速让新用户获得"高手级别的效果"。这样做的妙处是：
- **验证成本外包给了高手社区**：不用你自己试错，高手已经证明这个玩法有效
- **新用户入门时间大幅缩短**：不用学 6 个月才能用出高手的效果，现在开箱即用
- **形成网络效应**：用户一上来就能获得好体验，更容易 stay 和传播

## 典型案例

### [[产品卡片-Cursor|Cursor]]
在 Cursor 之前，有很多人试图用 ChatGPT 来辅助编程，也积累了一套玩法：怎么问 AI 才能获得更好的代码建议，怎么一步步引导 AI 理解你的需求，怎么用 AI 处理不同类型的任务（生成、重构、调试）。Cursor 团队观察了这些 power user 的工作流，把"Agent 模式"、"Codebase 理解"、"多轮迭代对话"等玩法直接内置成 IDE 的核心功能。新用户不需要学怎么用 ChatGPT 编程，Cursor 直接给出最佳实践。这也是为什么 Cursor 一出现就秒杀了其他 AI coding 工具——不是技术创新，而是把高手玩法产品化了。

### [[产品卡片-NotebookLM|NotebookLM]]
有很多人在用 ChatGPT 进行文献分析，积累了一套打法：怎么让 AI 理解整个文档的背景，怎么问问题才能得到更深层的洞察，怎么用不同的提问方式来理解同一份文档。NotebookLM 把这些玩法标准化成了产品功能：自动生成学习指南、播客讨论、Q&A 等。用户不需要学怎么用 AI 分析文献，产品直接就给出高手级的分析方式。

### [[产品卡片-Lovable|Lovable]]
有前端高手用 Claude 或 ChatGPT 进行网站开发，开发出了一套流程：从简单的 UI 描述开始，逐步完善和迭代，让 AI 去处理所有的编码细节，自己专注于交互逻辑和设计。Lovable 把这个玩法标准化成了"描述 UI → AI 生成代码 → 所见即所得编辑"的流程。没有编程经验的人现在也能像前端高手一样快速构建网站。

## 关键成功要素

1. **深度接触 power user**：不是看看论坛评论就行，要实际跟踪一些高手怎么用你的产品，观察他们的工作流、快捷键组合、思考方式。这是最关键的信息来源。
2. **识别"最高频、最有效"的玩法**：power user 有 100 种玩法，但只有 20% 的玩法被 80% 的 power user 频繁使用。抓住这些 pareto 规律的玩法。
3. **把隐性知识显性化**：高手的玩法往往是隐性的、直觉的。产品化的过程中，要把这些隐性知识变成显性的功能、UI flow、默认配置，这样普通用户才能直接受益。

## 常见误区

1. **把"复杂功能"和"高手玩法"搞混了**：高手玩法不是功能多、选项多，反而往往是"用最少的功能组合出最大的效果"。过度堆功能，反而阻碍了普通用户的使用。
2. **产品化后没有反馈机制**：high user 的玩法会一直在演进。产品化之后，要持续收集反馈，迭代这些产品化的玩法。否则很快就会落后于高手社区的新发现。
