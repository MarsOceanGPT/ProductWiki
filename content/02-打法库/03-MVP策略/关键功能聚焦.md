# 关键功能聚焦

> MVP 阶段，识别那一个"杀手级功能"，把其他的全部砍掉，只做这一件事到极致。

## 这个打法的本质

很多初创团队做产品时有个通病：想着"我要覆盖用户的所有场景"，结果做了笔记功能、做了协作功能、做了分析功能，每个功能都做得平平无奇。最后发现用户也不太用。

关键认知就是：**用户记住你，往往不是因为"你什么都能做"，而是因为"你在某一件事上做得特别好"**。Figma 不是因为全能的设计工具，而是因为"云端协作设计"这一件事做得无敌。Slack 不是因为功能多，而是因为"搜索和消息可靠性"这两个点做得完美。

聚焦的逻辑很简单：
- 时间有限 → 必须选择 → 选择意味着放弃
- 一个团队的全力投入，远强于分散投入的所有产品
- 当你把一件事做到 95 分时，用户会口碑传播；做到 60 分时，用户会无感

关键是找到那一个"杀手级功能"——如果这个功能做得好，用户愿意忍受其他功能的不足。比如 Cursor，如果 Tab 补全和 Agent 做得不够好，再漂亮的界面也没用。但因为这两个核心功能做得无敌，用户甚至不在乎 Cursor 没有某些 VS Code 插件。

## 典型案例

### [[01-产品库/产品卡片-Cursor|Cursor]]
Cursor 的聚焦点就是"最好的 AI 编程助手"。不做项目管理、不做 CI/CD、不做团队协作，就做一个事：把"人+AI"的编程体验做到最优。这种聚焦让 Cursor 的每个工程师都能全力投入"怎么让 AI 补全更准确、怎么让 Agent 模式更可靠"。结果就是远超竞品的体验。

### [[01-产品库/产品卡片-NotebookLM|NotebookLM]]
Google 做 NotebookLM 时，不是想做"全功能笔记应用"，而是聚焦在"基于你上传的资料进行 AI 对话"这一件事。不做笔记的美化、不做知识图谱、不做协作。就把"理解你的资料、回答你的问题、生成学习指南"这些事情做到极致。这个聚焦使得 NotebookLM 成为"最好的文献分析工具"，而不是"什么都不是很好的笔记应用"。

### [[01-产品库/产品卡片-Character.ai|Character.ai]]
聚焦在"和特定角色的对话"这一件事。不做社交网络、不做内容分发（虽然后来加了一些），就把"对话体验"和"角色多样性"做到最好。这个聚焦让 Character.ai 成为了"角色社交"这个品类的开创者。

### [[01-产品库/产品卡片-Perplexity|Perplexity]]
早期聚焦就是"比 Google 更聪明的搜索"。不做浏览器、不做邮件、不做文档，就做搜索+推理。这个聚焦让 Perplexity 在搜索市场有了清晰的差异化。

## 关键成功要素

1. **找对杀手级功能**：不是技术上最难的功能，也不是看起来最酷的功能，而是"用户最迫切需要、竞品最没做好"的那个功能。要通过深度用户访谈来确认。
2. **舍得砍功能**：这是最难的。创始人往往对自己的想法都有感情，很难砍掉。但 MVP 的定义就是"最小化"，过度设计反而是失败。
3. **做到 95 分再加新功能**：不是做到 60 分就加新功能。当杀手级功能已经做到"用户都在用、口碑都在传"的程度，再考虑加第二个功能。

## 常见误区

1. **把"简单"和"聚焦"搞混**：聚焦不是"功能少就行"，而是"选择一个维度，然后在这个维度上无敌"。简单的产品可能失焦，聚焦的产品可能很复杂。
2. **过早扩张功能**：很多团队在第一个功能还没有获得清晰的 PMF 时，就急着加第二个功能。结果是所有功能都平庸。要等到真正的 PMF 信号（高留存、高推荐）再扩张。
