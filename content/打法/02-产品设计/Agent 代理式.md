# Agent 代理式

> 用户定义目标，AI 自主分解任务、调用工具、执行多步骤工作流，最后给你一个完整的成果。

## 这个打法的本质

Agent 和普通 Chat 的区别，就像老板和员工的区别。Chat 是"我问一个问题，你回答一个问题"。Agent 是"我说一个需求，你自己想办法搞定，中间的所有细节我不管"。

具体来说，Agent 有几个关键特征：
- **自主分解**：AI 能理解一个复杂目标，自己拆成多个子任务
- **调用工具**：不仅仅输出文字，还能调用代码、搜索、API 等外部工具
- **迭代和自纠**：执行过程中出现问题，AI 能自己调整策略再试
- **完整交付**：最后不是"给你一个建议"，而是"给你一个可用的成果"

为什么这个模式威力大？因为**它把"执行成本"从用户转到了 AI**。用户原来要做的所有繁琐操作、判断、反复验证，现在 AI 都可以帮你做。这个转变，会改变整个使用体验。

想象一个场景：你跟 Manus 说"帮我做一份竞品分析，包括价格、功能对比、市场评价"。Manus 会自动去搜索、访问官网、读用户评价、整理成表格。你看最后的结果，不需要知道 AI 访问了多少个网页、读了多少篇评论。这就是 Agent 的威力——用户层面的体验，就是"一句话搞定了原来要花 2 小时的工作"。

## 典型案例

### [[产品/Cursor|Cursor]]
Cursor 的 Composer 模式就是 Agent 思维的应用。你描述一个需求，比如"给这个函数加上错误处理和日志"。Composer 不只是改一个地方，它会自动：找到相关的所有文件，理解现有的错误处理模式，保持代码风格一致，甚至自动导入缺失的库。用户只需要看最后的结果，决定要不要接受，完全不需要手动操作。

### [[产品/Manus|Manus]]
这是纯粹的 Agent 产品。你给它一个任务，它会自动打开浏览器、填表单、执行代码、存储结果。比如"从这 10 个竞品网站爬取定价信息"，Manus 会自动分析每个网站的结构、提取数据、整理成 CSV。整个过程用户是旁观者，最后直接拿数据。

### [[产品/Genspark|Genspark]]
搜索的 Agent 版本。你问一个问题，Genspark 不仅搜索、而且会自动：对比多个来源、识别最可信的信息、生成多个视角的答案（事实、分析、反对意见）、整理成逻辑清晰的报告。这些都是自动做的，不需要用户指挥。

## 关键成功要素

1. **任务的标准化程度要够高**：Agent 最适合那些"有明确目标、执行步骤相对固定"的任务。如果每次任务都很独特，没有规律可循，Agent 就容易出错。
2. **工具生态要齐全**：Agent 的威力来自能调用各种工具。如果工具有限，能力就有限。需要花大力气集成各种 API、能访问各种服务。
3. **容错能力要强**：因为 Agent 是自主执行，很容易出现"一步错、步步错"的连锁反应。需要强大的自我检测和纠错机制，以及清晰的失败恢复流程。

## 常见误区

1. **什么都想做成 Agent**：不是所有任务都适合 Agent。一些需要人类判断、创意、个性化偏好的任务，Agent 反而容易让人失控。比如"写一篇文章"，可能你想要的是 Copilot 模式（AI 建议，自己写），而不是 Agent 模式（AI 全自动写）。
2. **过度自动化导致用户感到"黑盒"**：如果用户完全看不到 AI 在做什么，一旦出问题就很难调试。好的 Agent 产品需要"透明的过程"——用户能看到每一步在做什么，如果不满意可以中断或调整。

## 搭配打法

### [[打法/02-产品设计/Copilot 范式|Copilot 范式]] 为什么搭配
Agent 是"我定义目标，AI 全自动"。Copilot 是"AI 建议，我决定"。在执行风险高的任务时，两者结合——先用 Copilot 建议，用户确认后再用 Agent 执行，安全性和可控性都提升。

### [[打法/03-MVP策略/关键功能聚焦|关键功能聚焦]] 为什么搭配
Agent 最容易失败的原因是"什么都想做"。应该先聚焦一个高频、高价值的任务做成 Agent，而不是试图构建"通用 Agent"。
